# 취준 템플릿 인덱스

## 역할

취준과 SSD Validation vault에서 사용하는 Markdown 템플릿의 목록과 선택 기준을 관리한다. 템플릿은 지식 노트가 아니므로 Global Graph에서는 `file:템플릿` 조건으로 제외한다.

## 템플릿 선택

| 목적 | 템플릿 | 사용 시점 |
| --- | --- | --- |
| 개념을 내 말로 설명 | [[개념 노트 템플릿]] | SSD/반도체 원리와 용어 정리 |
| 검증 항목 정의 | [[검증 포인트 노트 템플릿]] | 조건, metric, pass/fail, 한계 정리 |
| 외부 자료 보존 | [[문서 스크랩 템플릿]] | 문서·spec·blog·brochure 읽기 |
| 프로젝트 전체 지도 | [[프로젝트 허브 템플릿]] | 목표, 범위, 산출물, evidence 연결 |
| 분야별 탐색 지도 | [[허브 노트 템플릿]] | 여러 개념과 프로젝트 branch 연결 |
| 실험 결과 기록 | [[실험 리포트 템플릿]] | 조건 matrix, 결과, 해석, 재현성 기록 |
| 학습 문답 | [[문답 노트 템플릿]] | 내가 먼저 답하고 근거를 보완하는 학습 |
| 면접 답변 | [[면접 브리프 템플릿]] | 30초/1분 답변과 evidence 연결 |
| 단계 회고 | [[회고 노트 템플릿]] | 한 일, 결과, 한계, 다음 개선 정리 |

## 공통 metadata 기준

- `title`: 실제 노트 제목
- `tags`: 내용 분류. 템플릿 자체를 뜻하는 tag를 생성 노트에 남기지 않는다.
- `type`: concept, validation-point, project, source, report 등 노트 역할
- `status`: seed, growing, stable, archived
- `domain`: SSD, Semiconductor Test, Career Preparation 등 지식 영역
- `source_type`: spec, vendor-blog, local-project, personal-experiment 등 출처 유형
- `reliability`: 출처와 관찰 범위에 대한 1차 판단
- `related_projects`, `related_roles`: 프로젝트와 직무 연결

## 사용 원칙

- 모든 문서를 하나의 템플릿에 억지로 맞추지 않는다.
- 외부 원문은 source template, 내 해석은 concept/validation template로 분리한다.
- 템플릿의 빈 `[[ ]]`는 실제 노트를 만들 때 삭제하거나 정확한 링크로 바꾼다.
- 생성한 노트는 해당 분야 허브에서 한 번 이상 링크한다.
