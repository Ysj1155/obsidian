## 답변 기본 구조

```text
질문 의도
  -> 한 문장 결론
  -> 내가 한 구체적 행동
  -> 관찰한 수치·trace·test evidence
  -> 해석의 한계
  -> 지원 직무에서의 활용
```

## 우선 준비할 질문

- 왜 SSD Validation/Test 직무인가?
- fio benchmark와 제품 validation은 무엇이 다른가?
- 평균 IOPS만 보면 왜 부족한가?
- QD가 커질 때 throughput과 p99 latency가 어떻게 달라지는가?
- 실제 SSD와 simulator 결과를 왜 분리해 설명해야 하는가?
- 실패한 가설이나 관측 제한을 어떻게 보고했는가?
- Fault injection과 invariant가 validation에서 어떤 역할을 하는가?
- 협업 중 재현되지 않는 문제를 어떻게 다룰 것인가?

## 운영 원칙

- 주장마다 실제 파일, 수치, test 또는 trace 근거를 연결한다.
- 내가 직접 하지 않은 일과 simulator 밖의 실제 firmware 동작을 과장하지 않는다.
- 30초 답변과 1분 답변은 결론은 같고 세부 깊이만 다르게 만든다.
- 회사별 답변은 최신 공고의 업무와 요구 역량에 맞춰 다시 조정한다.
