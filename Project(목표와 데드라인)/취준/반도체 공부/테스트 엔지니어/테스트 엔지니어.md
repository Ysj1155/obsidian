# 테스트 엔지니어 허브

## 이 허브의 역할

반도체 전기적 검사, ATE resource, analog measurement, 후공정·양산 test와 SSD system validation의 공통점과 차이를 정리한다.

- 상위 허브: [[반도체 공부]]
- 제조 흐름: [[9대 공정|반도체 9대 공정 허브]]
- 제품 검증: [[SSD 허브]]

## 기본 직무 지도

```text
Wafer EDS
  -> package / final test
  -> module·board test
  -> SSD firmware·system validation
  -> qualification / reliability / failure analysis
```

각 단계는 DUT, interface, fault model, 비용과 관측 가능성이 다르다. 공통점은 test condition을 통제하고 expected result와 실제 결과의 차이를 근거로 판단한다는 점이다.

## 공통 검증 사고

- DUT와 test boundary를 먼저 정의한다.
- Stimulus, condition, expected result, measured result를 분리한다.
- Pass/Fail뿐 아니라 측정 coverage와 observer limitation을 기록한다.
- Test time을 줄일 때 놓치는 defect class와 correlation 근거를 확인한다.
- 불량 재현, 가설, 분리 실험, 원인 확인, 재발 방지를 단계로 나눈다.

## 자료를 읽을 때 주의할 점

- 이 폴더의 일부 노트는 교육·웹 자료를 옮긴 원문이므로 현재 표준과 장비별 차이를 추가 확인한다.
- Analog IC test와 SSD validation은 같은 도구를 쓰는 분야가 아니다. 검증 구조가 대응되는 부분만 연결한다.
- Short-stroke나 sampling은 test-time 절감 아이디어이지 full-capacity qualification을 자동 대체하지 않는다.
