# SSD Validation Engineer 24주 로드맵
> 목적: `fio 기반 SSD 검증 체계`를 중심축으로 두고, `sustained latency/QoS`, `system integration 관점`, `ML I/O(DLIO/MLPerf Storage)`까지 확장하는 24주 학습·실습·문서화 계획  
> 사용 방식: 이 문서를 **주간 체크리스트 + 피드백 로그 + 포트폴리오 템플릿**으로 사용한다.

---

## 0. 이 문서의 원칙

### 최종 목표
24주가 끝났을 때 아래 4가지를 말할 수 있어야 한다.

1. **Ubuntu/Linux 환경에서 반복 가능한 SSD 성능 검증 체계를 직접 구성했다.**
2. **평균 속도뿐 아니라 tail latency, QoS, sustained workload까지 분석했다.**
3. **조건-로그-재현-분석 흐름으로 root-cause 후보를 좁히는 사고방식을 훈련했다.**
4. **전통적인 block I/O benchmark를 넘어 DLIO, MLPerf Storage 관점까지 연결했다.**

### 운영 원칙
- 매주 **새 툴 1개**보다 **새 산출물 1개**를 우선한다.
- 모든 실험은 가능한 한 **재현 가능**해야 한다.
- 숫자만 적지 말고 **조건**, **의도**, **해석**, **한계**를 반드시 적는다.
- 그래프 없는 결과 정리는 반쪽짜리다.
- 실험 실패도 기록한다. 실패한 이유 자체가 검증 역량이다.

# 7. 마지막 문장

이 로드맵의 목적은 “벤치마크 도구를 많이 써본 사람”이 되는 것이 아니다.  
목표는 **실험을 검증으로 바꾸고, 결과를 해석 가능한 언어로 남기고, 저장장치 엔지니어의 관점으로 시스템을 보는 사람**이 되는 것이다.

속도보다 누적이 중요하다.  
한 주에 완벽함을 만들기보다, **24주 동안 흔적이 남는 구조**를 만드는 쪽이 맞다.
